ЗАДАЧА 10: USACO 2025. Февруарско състезание, Сребърна група. Трансформиране на двойки
(Transforming Pairs)

⏱️ Време: 2 с.
💾 Памет: 256 MB
🏫 Школа МГ
⚡ Сложност: O(log(max(c, d)))

Вход

Първият ред на входа въвежда четири цели числа a, b, c и d, разделени с интервал.

Изход

На единствения ред на стандартния изход програмата да извежда едно цяло число — търсеният минимален брой операции.

Анализ

Движим се отзад напред: от (c, d) към (a, b). Проверяваме дали сме достигнали точно началната двойка. Ако първото число вече съвпада, проверяваме дали можем да намалим второто до b. Ако второто число вече съвпада, проверяваме дали можем да намалим първото до a.

Прилагаме бързата стъпка на Евклид с деление. Ако c == d, но не сме достигнали a и b, не можем да продължим.

Разбивка на случаите при движение назад

1. Проверка за успех или невъзможност

Ако c == a и d == b, сме достигнали целта! Ако обаче в някой момент c < a или d < b, значи сме подминали началните стойности и връщаме -1.

2. Когато едното число вече съвпада (c == a или d == b)

Ако c == a, повече не бива да променяме първото число. Остава единствено да проверим дали разликата d - b се дели точно на c: ако (d - b) % c == 0, добавяме (d - b) / c операции и приключваме. Аналогично, ако d == b, проверяваме дали (c - a) % d == 0.

3. Бърза стъпка на Евклид с деление

Когато и двете числа са по-големи от началните: ако c > d, добавяме c / d към броя на операциите и заменяме c с остатъка c % d. Ако d > c, добавяме d / c към операциите и заменяме d с d % c. Ако c == d, спираме с -1.

🧭 Как алгоритъмът избира следващия ход?

На всяка итерация от цикъла програмата проверява следните условия в точен ред. Кликнете върху някой от бутоните по-долу, за да осветите кой случай се задейства!

1. Първото число съвпада (c == a)

Вече не променяме c. Проверяваме дали (d - b) % a == 0. Ако да, добавяме (d - b) / a стъпки и успяваме! Иначе извеждаме -1.

2. Второто число съвпада (d == b)

Вече не променяме d. Проверяваме дали (c - a) % b == 0. Ако да, добавяме (c - a) / b стъпки и успяваме! Иначе извеждаме -1.

3. Първото е по-голямо (c > d)

Прилагаме бързата стъпка на Евклид: добавяме c / d към брояча на операциите и намаляваме c = c % d.

4. Второто е по-голямо (d > c)

Прилагаме бързата стъпка на Евклид: добавяме d / c към брояча на операциите и намаляваме d = d % c.

Защо не правим просто c % d, когато d == b?
Ако a = 5, b = 3 и сме стигнали до c = 8, d = 3, операцията 8 % 3 би намалила c директно на 2, прескачайки началната стойност a = 5! Затова проверката за съвпадение на едното число винаги се прави преди общата стъпка на Евклид.
