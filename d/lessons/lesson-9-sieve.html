Решето на Ератостен — Идея, алгоритъм и основни приложения

🏫 Група D
⚡ Сложност: O(n log log n)
💾 Памет за 107: ~10 MB (bool)
🎯 Факторизация: O(log x)

1. Идея, алгоритъм и ключови оптимизации

Ако проверяваме всяко число поотделно дали има делител до корен квадратен от него, за всички числа до n = 107 ще направим около 3 · 1010 операции и ще получим Time Limit Exceeded (TLE).

💡 Идеята на Ератостен

Ератостен обръща логиката: вместо да търсим делители на всяко число, задраскваме кратните на простите числа!

❓ Въпрос: Ако вече знаем, че 2 е просто число, какво можем веднага да кажем за 4, 6, 8, 10, … без изобщо да проверяваме дали се делят на други числа?
Всички те се делят на 2 (и са по-големи от 2), следователно със сигурност са съставни и можем мигновено да ги задраскаме!

Стъпки на алгоритъма:

  1. Отбелязваме всички числа от 2 до n като „незадраскани“ (p[i] = true). Числата 0 и 1 не са прости (p[0] = p[1] = false).
  2. Взимаме първото незадраскано число i (започваме от i = 2). То със сигурност е просто, защото никое по-малко число не го е разделило.
  3. Задраскваме всички негови кратни в таблицата (p[j] = false).
  4. Продължаваме със следващото незадраскано i.

Двете ключови оптимизации:

❓ Оптимизация 1: Когато стигнем до простото число i = 5, има ли смисъл да задраскваме 5·2 = 10, 5·3 = 15 и 5·4 = 20?
Няма смисъл! Всички кратни от вида i · k (за k < i) вече са били задраскани на по-ранна стъпка от простите делители на k (напр. 10 и 20 от 2, а 15 от 3). Първото кратно на i, което все още НЕ е задраскано, е i · i (за i = 5 това е 25)!
❓ Оптимизация 2: Ако n = 20, на стъпка i = 5 първото число за задраскване е 5·5 = 25 (извън таблицата). До кое условие за i върти външният цикъл?
Външният цикъл за задраскване трябва да върти само докато i * i ≤ n! Всички незадраскани числа след корен квадратен от n автоматично са прости.

Пример: Класическо решето на Ератостен (resheto.cpp)

Програмата чете n (n ≤ 107) и извежда всички прости числа до n. Масивът p е глобален, за да се задели в статичната памет (около 10 MB за 107 елемента от тип bool), където автоматично е инициализиран с false.

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 10000005;
bool p[MAXN];

int main()
{
    int n;
    cin >> n;
    for(int i = 2; i <= n; i++) p[i] = true;

    for(int i = 2; i * i <= n; i++)
    {
        if(p[i])
        {
            for(int j = i * i; j <= n; j += i) p[j] = false;
        }
    }
    for(int i = 2; i <= n; i++)
    {
        if(p[i]) cout << i << " ";
    }
    cout << "\n";
}

2. Приложение 1: Брой прости числа в интервал [l, r]

Дадени са q (q ≤ 105) заявки с интервали [l, r] (1 ≤ l ≤ r ≤ 106). За всяка заявка трябва да изведем колко са простите числа в [l, r].

Дори да сме пуснали решето предварително, обхождането от l до r с цикъл за всяка от 105 заявки ще направи до 1011 стъпки (TLE).

🚀 Решение за O(1) на заявка чрез префиксни суми

Строим масив от префиксни суми s[i], който пази броя на простите числа от 1 до i. Тогава отговорът за всеки интервал [l, r] е просто s[r] - s[l - 1]!

for(int i = 1; i <= mx; i++)
{
    s[i] = s[i - 1];
    if(p[i]) s[i]++;
}
// За всяка заявка [l, r]:
if(l < 1) l = 1;
cout << s[r] - s[l - 1] << "\n";

3. Приложение 2: Най-малък прост делител d[x] и факторизация за O(log x)

Това е най-важното състезателно приложение на решетото! Ако трябва да разложим q = 105 числа (до 107) на прости множители, стандартната проверка до корен квадратен от x за всяко число е твърде бавна.

Вместо true / false, за всяко число пазим кое просто число го е задраскало първо — неговия най-малък прост делител d[x]. Например за 60:

  • Взимаме d[60] = 2 и делим: 60 / 2 = 30.
  • Взимаме d[30] = 2 и делим: 30 / 2 = 15.
  • Взимаме d[15] = 3 и делим: 15 / 3 = 5.
  • Взимаме d[5] = 5 и делим: 5 / 5 = 1 → спираме! Прости множители: 2, 2, 3, 5.

На всяка стъпка числото намалява поне наполовина, затова разлагането на число до 107 прави най-много 23 деления!

⚠️ Тънкости в кода на delitel.cpp

Първоначално задаваме d[i] = i. Вътре във вложения цикъл записваме d[j] = i само ако d[j] == j (тоест числото j все още не е пипано от по-малък прост делител — така за 12 ще остане d[12] = 2, а няма да се презапише с 3)!

4. Приложение 3: Брой различни прости делители c[x]

Търсим за всяко число от 2 до n колко различни прости делителя има (например 12 = 22 · 3 има 2 различни прости делителя: 2 и 3).

❓ Въпрос: Защо в diff.cpp външният цикъл върти чак до n (а не до i * i ≤ n), и вътрешният цикъл започва от i (а не от i * i)?
1. Външният цикъл трябва да стигне чак до n, защото простите числа, по-големи от корен квадратен от n (например 5, 7, 11 при n = 12), също трябва да прибавят +1 на себе си и на своите кратни (напр. 5 дели 10)!
2. Вътрешният цикъл тръгва от j = i, защото както самото просто число i, така и кратните му преди i · i (като 6 = 2 · 3 при i = 3) трябва да отчетат i като свой прост делител! 
for(int i = 2; i <= n; i++)
{
    if(c[i] == 0) // Числото i е просто!
    {
        for(int j = i; j <= n; j += i) c[j]++;
    }
}

5. Приложение 4: Брой и сума на всички делители („Решето на делителите“)

Какво се случва, ако махнем проверката за просто число и пуснем кратните на всяко число i от 1 до n? Тогава всяко i посещава точно онези числа j, на които i е делител!

  • c[j]++ преброява всички положителни делители на j.
  • s[j] += i намира сумата на всички делители на j (пазим я в long long).
  • Сложност: Вътрешният цикъл прави n/1 + n/2 + n/3 + … + n/n ≈ n ln n стъпки — т.е. O(n log n), което за n = 106 работи отлично!

6. Базови задачи за упражнение

Кликнете върху някоя от трите задачи по-долу, за да я тествате интерактивно в десния панел:

Базова задача 1: Прости близнаци 2 ≤ n ≤ 106

Дадено е цяло число n. Изведете всички двойки прости числа (a, b) с b ≤ n, за които b − a = 2. Пример за n = 20: (3, 5), (5, 7), (11, 13), (17, 19).

Насока: Пуснете класическо решето до n, след което обходете i от 2 до n − 2 и проверявайте p[i] && p[i + 2].

Базова задача 2: Числа с точно три делителя q ≤ 105, x ≤ 1012

Дадени са q цели числа x. За всяко изведете YES, ако има точно 3 положителни делителя, или NO иначе. Пример за 4, 6, 49 → YES, NO, YES (делителите на 49 са 1, 7, 49).

Насока: Нечетен брой делители имат само точните квадрати, а точен квадрат r2 няма други делители освен 1, r, r2 точно когато r е просто число до 106!

Базова задача 3: Почти прости числа (k-прости в интервал) 1 ≤ l ≤ r ≤ 106, 1 ≤ k ≤ 7

Дадени са q заявки (l, r, k). Изведете колко числа в [l, r] имат точно k различни прости делителя. Пример за l = 1, r = 10, k = 2 → 2 (числата 6 = 2·3 и 10 = 2·5).

Насока: Пресметнете c[x] чрез diff.cpp и изградете 7 масива от префиксни суми pref[k][i] за всяко k от 1 до 7!
