1. Какво е интерактивна задача и протоколът „?“ / „!“

В стандартните задачи програмата получава всички входни данни наведнъж и накрая отпечатва отговора. При интерактивните задачи входът е скрит! Вашата програма води диалог в реално време със специална програма на журито, наречена Interactor (Интерактор).

В международните платформи (Codeforces, AtCoder, информатични турнири) най-често се използва стандартният протокол с два вида съобщения:

  • ? параметри — Заявка (Query): Питате журито за информация (напр. ? 5 пита каква е стойността на 5-ия елемент). След това задължително четете отговора с cin >> resp;.
  • ! отговор — Финален отговор (Answer): Когато сте сигурни в решението, отпечатвате ! X и веднага прекратявате програмата (return 0;). Финалният отговор обикновено не се брои към лимита на заявките!
// Помощна функция за чист код при интерактивни заявки:
int ask(int x) {
    cout << "? " << x << endl; // Изпращаме заявката веднага
    int ans;
    cin >> ans;                // Четем отговора от журито
    return ans;
}

2. Буфериране на потоци, Deadlock и ILE

Когато изпълните cout << "? 5\n";, C++ не изпраща текста веднага към журито, а го съхранява във вътрешен буфер („пощенска кутия“), за да пести време. Ако веднага след това извикате cin >> ans;, вашата програма чака отговор от журито, а журито чака вашия въпрос, който още стои в буфера!

Получава се вечно изчакване (Deadlock), което води до специфичния вердикт Idleness Limit Exceeded (ILE) или Time Limit Exceeded.

🚨 Как да избегнем Deadlock (ILE)?

След всяко отпечатване използвайте cout << endl; (което поставя нов ред И автоматично изпразва буфера чрез flush) или изрично cout << flush;. При използване на printf извиквайте fflush(stdout);.

⚠️ Внимание с бързия вход/изход: cin.tie(NULL)

По подразбиране в C++ потоците cin и cout са свързани — преди всяко четене с cin буферът на cout се изпразва автоматично. Ако обаче напишете cin.tie(NULL); и използвате '\n' вместо endl, разкъсвате тази връзка и програмата ви гарантирано ще блокира!

3. Класическа игра: „Познай числото“ с двоично търсене

Журито си е намислило тайно число X в интервала [1, N], където N = 100, и ви дава право на най-много 7 въпроса. На всеки въпрос mid журито отговаря с:

  • "<" — ако тайното число е строго по-малко от mid (търсим в [L, mid - 1]);
  • ">" — ако тайното число е строго по-голямо от mid (търсим в [mid + 1, R]);
  • "=" — ако сте познали числото!

Достатъчни само 30 въпроса!

4. Задачи с Grader (Локална библиотека на НОИ / IATI)

На българските олимпиади по информатика (НОИ, Есенен и Пролетен турнир) интерактивните задачи често НЕ използват cin и cout! Вместо това се компилират заедно със служебен файл на журито (Grader) чрез заглавен файл, напр. #include "guess.h".

  • НЕ пишете функция int main()! (Тя вече съществува в грейдъра на журито).
  • Имплементирате само исканата от условието функция (напр. int solve(int n)) и вътре в нея извиквате готовите функции на журито (напр. char res = query(mid);).
  • Предимство: Няма нужда от endl и flush, защото комуникацията става чрез директни извиквания на C++ функции!
#include "guess.h" // Включваме библиотеката на журито (БЕЗ main функция!)

int findNumber(int n) {
    int L = 1, R = n;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        int cmp = askJury(mid); // Функция, предоставена от журито
        if (cmp == 0) return mid;
        if (cmp < 0) R = mid - 1;
        else L = mid + 1;
    }
    return L;
}

5. Адаптивно жури, Кеширане на заявки и код за грешка (-1)

Три професионални техники, които разделят 0 точки от 100 точки на състезание:

  1. Кеширане (Мемоизация) на заявки: Ако алгоритъмът ви случайно провери един и същ индекс два пъти, не хабете втора заявка! Пазете отговорите в масив memo[x].
  2. Проверка за невалидна заявка (-1): Когато надвишите лимита от въпроси, интеракторът обикновено връща -1 и се затваря. Ако програмата ви не провери за if (ans == -1) exit(0);, тя ще продължи да чете от затворен поток и ще получи Time Limit Exceeded вместо коректния вердикт Wrong Answer!
  3. Адаптивно жури (Adaptive Interactor): В някои задачи журито няма предварително фиксирано число, а поддържа множество от всички възможни кандидати, които не противоречат на досегашните му отговори, за да ви затрудни максимално!

6. Приложни състезателни задачи

Изберете една от трите класически интерактивни задачи по-долу, за да я разгледате и трасирате стъпка по стъпка в десния панел:

Задача А: Откриване на по-тежка фалшива монета O(log N) претегляния

Сред N монети всички тежат по 10 г, а точно една е фалшива и тежи 11 г. Със заявки ? L mid питаме за сумата в лявата половина [L, mid]. Ако сумата е по-голяма от (mid - L + 1) * 10, фалшивата монета е вляво!

Задача Б: Локален максимум (Връх в планински масив) O(log N) заявки

Масивът е скрит. В една стъпка питаме за два съседни елемента ? mid и ? mid + 1. Ако a[mid] < a[mid + 1], значи се изкачваме нагоре и върхът е вдясно (L = mid + 1), иначе е вляво (R = mid).

Задача В: Възстановяване на скрита пермутация със суми N - 1 заявки

Журито крие пермутация на числата от 1 до N. Питаме последователно за сумите a[1] + a[2], a[2] + a[3] и т.н., а последния елемент намираме от общата сума N(N+1)/2, за да спестим решаващата последна заявка!
