Едномерни и двумерни задачи (Bottom-Up ДП)

🎓 Група C: 7–8. клас
⏱️ Време: 60 мин
📦 Ключови понятия: 1D и 2D ДП, Pull vs Push, Мрежи с препятствия, Оптимизация на паметта

🚀 Философията на Bottom-Up (Отдолу-нагоре)

Вместо да тръгваме от голямото число N и да се спускаме с рекурсия, при Bottom-Up подхода започваме от най-малките базови случаи (0 и 1) и с обикновени for цикли строим таблицата последователно до N!

1. Едномерно ДП (1D DP) — Състояние и попълване

Използваме едномерен масив dp[i], когато всяка подзадача се описва напълно само с един параметър — индекса i (например позиция в редица, сума в лева или номер на стъпало).

  • Състояние: dp[i] е „склад“, в който пазим готовия отговор за подпроблема с размер i.
  • Златно правило за реда на цикъла: Преди да пресметнем dp[i], всички клетки, от които то зависи (напр. dp[i - 1] и dp[i - 2]), трябва вече да са сметнати! Затова цикълът върви от малките индекси към големите.
long long fib(int n) {
    vector<long long> dp(n + 1, 0);
    dp[0] = 0; // Базов случай 0
    dp[1] = 1; // Базов случай 1
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2]; // Преход от вече готовите клетки
    }
    return dp[n];
}

2. Два начина на мислене: Pull DP срещу Push DP

Много важна състезателна концепция, която улеснява писането на формулите при Bottom-Up ДП, е изборът между двата вида преходи:

  1. „Издърпващо“ ДП (Pull DP — Откъде идвам?): Заставаме на клетка i и питаме от кои предходни клетки сме могли да скочим тук:
    dp[i] = dp[i - 1] + dp[i - 2];
  2. „Избутващо“ ДП (Push DP — Накъде отивам?): Заставаме на вече сметнатата клетка i и „раздаваме“ нейната стойност напред към всички клетки, до които можем да скочим от нея:
    dp[i + 1] += dp[i]; и dp[i + 2] += dp[i];

💡 Кога Push DP е по-удобно?

Когато от клетка i правилата за скок зависят от стойността в масива A[i] (напр. „от клетка i можеш да скочиш с точно A[i] позиции напред“). Тогава с Push DP просто пишем dp[i + A[i]] += dp[i];!

3. Двумерно ДП (2D DP) — Пътища в таблица

Когато подпроблемът зависи от два параметъра (например ред i и колона j в матрица), използваме двумерна таблица dp[i][j].

Класическа задача: В мрежа с размери N × M тръгваме от горния ляв ъгъл (0, 0) и искаме да стигнем до долния десен ъгъл (N - 1, M - 1), като се движим само надолу и надясно. По колко различни начина можем да го направим?

  • Състояние: dp[i][j] = брой пътища от старта до клетка (i, j).
  • Базови случаи: Целият първи ред dp[0][j] = 1 (има само 1 път — само надясно) и цялата първа колона dp[i][0] = 1 (само надолу).
  • Преход: В клетка (i, j) можем да влезем само отгоре (i - 1, j) или отляво (i, j - 1):
    dp[i][j] = dp[i - 1][j] + dp[i][j - 1];

4. Мрежи с препятствия и трикът с 1-базираната рамка

В реалните състезателни задачи в мрежата почти винаги има препятствия (стени/капани), през които не може да се минава, и кодът трябва да бъде защитен от излизане извън границите на масива.

  • Как се обработва стена: Ако клетка (i, j) е блокирана (напр. grid[i][j] == '#'), просто полагаме dp[i][j] = 0 (през нея минават 0 пътя!).
  • Професионален трик (1-базирана рамка / Padding): Вместо да пишем отделни цикли за нулевия ред и нулевата колона (които се чупят, ако на първия ред има стена!), дефинираме таблицата с размер (N + 1) × (M + 1), запълнена с 0, и индексираме от 1 до N! Тогава нулевият ред и нулевата колона служат като автоматична „предпазна стена“ от нули!
// Универсален шаблон за 2D ДП с препятствия (1-базирано):
vector<vector<long long>> dp(N + 1, vector<long long>(M + 1, 0));
if (grid[1][1] != '#') dp[1][1] = 1; // Стартова клетка

for (int i = 1; i <= N; i++) {
    for (int j = 1; j <= M; j++) {
        if (i == 1 && j == 1) continue;
        if (grid[i][j] == '#') dp[i][j] = 0; // Стена!
        else dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
    }
}

5. Оптимизация на паметта (Space Optimization)

Забелязахте ли нещо много важно? За да сметнем dp[i] във Фибоначи, ни трябват само предните две числа (dp[i - 1] и dp[i - 2]) — по-старите клетки dp[0..i-3] никога повече не се използват!

ЗадачаСтандартна паметОптимизирана паметКак се прави?
1D ДП (Фибоначи)O(N) масивO(1) (3 променливи)Пазим само prev2, prev1 и cur.
2D ДП в таблицаO(N × M) матрицаO(M) (1 ред)Пазим само един вектор dp[j] += dp[j - 1]!

Тази техника спасява решението ви от Memory Limit Exceeded (MLE) при големи таблици (напр. 10 000 × 10 000)!

6. Класически приложни задачи (1D и 2D Bottom-Up)

Кликнете върху някоя от трите златни класики в състезателното програмиране по-долу, за да я разгледате и трасирате в десния панел:

Задача А: Костенурката — Максимална сума в таблица 2D Оптимизационно ДП

Всяка клетка (i, j) съдържа A[i][j] монети. Движим се само надолу и надясно. Намерете максималния брой монети по пътя до (N, M): dp[i][j] = A[i][j] + max(dp[i - 1][j], dp[i][j - 1]).

Задача Б: Размяна на сума с минимален брой монети (Coin Change) 1D ДП по сума

Имаме монети с номинали {1, 3, 4} и търсим минималния брой монети за сума S = 6. Забележете: Алчният алгоритъм взима 4 + 1 + 1 (3 монети — ГРЕШНО!), а ДП намира 3 + 3 (2 монети)!

Задача В: Най-дълга нарастваща подредица (LIS) O(N2) Класическо ДП

За всеки елемент A[i] търсим най-дългата строго растяща подредица, завършваща в индекс i, като проверяваме всички предходни елементи j < i с A[j] < A[i]: dp[i] = max(dp[i], dp[j] + 1).
