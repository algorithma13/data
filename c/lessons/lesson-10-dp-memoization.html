Динамично програмиране: Рекурсия и Мемоизация

🎓 Група C: 7–8. клас
⏱️ Време: 60 мин
📦 Ключови понятия: Припокриващи се подзадачи, Top-Down (memo), Bottom-Up (dp)

💡 Златното правило на Динамичното програмиране

„Тези, които не помнят миналото, са осъдени да го пресмятат отново!“ — Никога не решавай един и същ подпроблем два пъти.

1. Същност на ДП и двете му фундаментални свойства

Динамичното програмиране (ДП) е мощна алгоритмична техника, при която разбиваме сложна задача на по-малки подзадачи, решаваме всяка подзадача само веднъж и записваме отговора ѝ в таблица („бележник“).

За да бъде една задача решима с Динамично програмиране, тя трябва да притежава две задължителни свойства (които често отличават ДП от алчните алгоритми и „Разделяй и владей“):

  1. Припокриващи се подзадачи (Overlapping Subproblems): При рекурсивното разбиване на задачата едни и същи малки подзадачи се извикват многократно.
  2. Оптимална подструктура (Optimal Substructure): Оптималното решение на голямата задача може да се сглоби директно от оптималните решения на нейните подзадачи.

Четирите стъпки за решаване на всяка ДП задача:

  • 1. Дефиниране на състоянието: Какво точно означава dp[i] (напр. „минималната цена да стигнем до стъпало i“)?
  • 2. Базови случаи (Дъно): Кои са най-малките стойности, чийто отговор знаем директно (напр. dp[0] = 0, dp[1] = 1)?
  • 3. Рекурентна връзка (Преход): Формулата, по която изчисляваме dp[i] чрез предходните състояния.
  • 4. Ред на изчисление и Финален отговор: В коя клетка на таблицата се намира крайният отговор (обикновено dp[n])?

2. Капанът на чистата рекурсия (Експоненциален взрив)

Да разгледаме класическата редица на Фибоначи: fib(0) = 0, fib(1) = 1 и fib(n) = fib(n - 1) + fib(n - 2) за всяко n ≥ 2.

long long fib_slow(int n) {
    if (n <= 1) return n;
    return fib_slow(n - 1) + fib_slow(n - 2);
}

🚨 Защо чистата рекурсия получава Time Limit Exceeded (TLE)?

За да пресметне fib(5), функцията пресмята fib(3) два пъти, а fib(2) — три пъти! Дървото на извикванията се удвоява на всяко ниво и има сложност O(2N). За fib(50) са нужни над 20 милиарда операции (десетки секунди), докато лимитът по състезания е около 108 операции за 1 секунда!

3. Мемоизация (Top-Down ДП — отгоре надолу)

Мемоизацията превръща бавната рекурсия в мълниеносно решение само с 3 реда код! Създаваме масив („бележник“) memo[N], запълнен със специална стойност -1 („още не е пресметнато“):

  1. Преди да правим рекурсивни извиквания за n, проверяваме: if (memo[n] != -1) return memo[n];.
  2. Ако стойността все още е -1, пресмятаме отговора и задължително го записваме в бележника преди да го върнем: return memo[n] = fib(n - 1) + fib(n - 2);.
long long memo[105]; // Първоначално запълнен с -1 чрез memset или цикъл

long long fib_memo(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n]; // Вече е сметнато -> връщаме веднага!
    return memo[n] = fib_memo(n - 1) + fib_memo(n - 2);
}

Така всяко състояние от 2 до N се изчислява точно по веднъж! Времевата сложност пада от експоненциална O(2N) на линейна O(N)!

4. Табулация (Bottom-Up ДП — отдолу нагоре с цикъл)

Вместо да тръгваме от голямото число N надолу с рекурсия (Top-Down), можем да попълним масива dp[] итеративно от най-малките подзадачи към най-голямата с обикновен for цикъл! Този подход се нарича Табулация (Bottom-Up ДП).

dp[0] = 0;
dp[1] = 1;
for (int i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
}

5. Чести капани и грешки на състезания

Дори при вярна формула, много състезатели губят точки заради следните четири технически капана (които сме пропуснали в старата версия на урока):

  1. Препълване на int (Integer Overflow): Резултатите в ДП растат изключително бързо! Още при fib(47) = 2 971 215 073 надхвърляме 32-битовия int. Винаги използвайте long long или смятайте по модул (напр. % 1000000007).
  2. Грешна начална стойност в memo: Ако в задачата валидният отговор може да бъде отрицателно число (включително -1), не ползвайте -1 за маркер „несметнато“! Тогава програмата ще пресмята състоянията с отговор -1 отново и отново (TLE). Ползвайте булев масив bool visited[N] или -INF.
  3. Бърза инициализация с memset: Функцията memset(memo, -1, sizeof(memo)); работи само за 0 и -1 (защото запълва паметта байт по байт). За произволни числа използвайте fill(memo, memo + n + 1, VAL) или vector<long long> memo(n + 1, -1).
  4. Възстановяване на пътя (Path Reconstruction): Често освен минималната цена се иска да отпечатаме и самите стъпки! За целта пазим втори масив parent[i], в който записваме от кое предходно състояние сме дошли в i.

6. Класически приложни задачи с 1D Динамично програмиране

Кликнете върху някоя от трите фундаментални задачи по-долу, за да разгледате нейната рекурентна връзка и да я трасирате стъпка по стъпка в десния панел:

Задача А: Стълбичка — Брой начини на изкачване Комбинаторно ДП

Имате стълба с N стъпала. На всяка крачка можете да се качите с 1 или с 2 стъпала. По колко различни начина можете да стигнете до връх N? Формула: dp[i] = dp[i - 1] + dp[i - 2].

Задача Б: Жабокът от AtCoder (Frog 1) — Минимална цена Оптимизационно ДП

Жабок скача по камъни с височини H[1..N] от камък i към i + 1 или i + 2 с цена |H[i] - H[j]|. Търсим минималната обща цена до камък N: dp[i] = min(dp[i-1] + |H[i]-H[i-1]|, dp[i-2] + |H[i]-H[i-2]|).

Задача В: Максимална сума без съседни елементи (Обир на къщи) ДП с избор Вземи / Пропусни

Даден е масив от положителни числа A[1..N]. Изберете подмножество от числа без две съседни с максимална сума: dp[i] = max(dp[i - 1], dp[i - 2] + A[i]).
