Монотонен стек

Принцип на работа, линейна сложност и класически състезателни приложения

Принцип на работа

Обикновен стек срещу Монотонен стек

  • Обикновен стек (std::stack): принцип LIFO (Last In, First Out – последен влязъл, първи излязъл).
  • Монотонен стек: обикновен стек, към който добавяме едно единствено правило: елементите в него (от дъното към върха) трябва винаги да бъдат подредени в строго растящ или строго намаляващ ред.

Аналогия: Редица от сгради

  • Представете си редица от сгради с различна височина, подредени от ляво надясно.
  • Заставате на покрива на всяка сграда и гледате наляво, за да видите коя е първата по-висока сграда, която ви закрива хоризонта.
  • Ако текущата сграда е с височина 10 метра, а пред нея има сгради с височини 4 м и 6 м, те се оказват напълно скрити зад новата 10-метрова сграда.
  • За всяка следваща сграда по-нататък вдясно тези ниски сгради (4 м и 6 м) са абсолютно безполезни — те никога няма да бъдат видими, защото 10-метровата сграда пред тях ги засенчва.
  • Затова можем завинаги да ги изхвърлим от паметта (да направим pop от стека), преди да добавим новата сграда.

Монотонно намаляващ стек

  • От дъното към върха стойностите намаляват.
  • Преди да добавим елемент X, изваждаме всички елементи от върха, които са по-малки или равни на X.
  • Използва се за намиране на най-близък по-голям елемент.

Монотонно растящ стек

  • От дъното към върха стойностите растат.
  • Преди да добавим елемент X, изваждаме всички елементи от върха, които са по-големи или равни на X.
  • Използва се за намиране на най-близък по-малък елемент.

Защо сложността по време е O(N), а не O(N2)?

В кода на монотонния стек винаги имаме вложен цикъл while вътре в основния цикъл for. На пръв поглед това изглежда квадратично, но реалната сложност е линейна — O(N).

Анализ:
  • Всеки от N-те елемента влиза в стека (push) точно веднъж.
  • Всеки елемент може да бъде изваден от стека (pop) най-много веднъж през цялото изпълнение на програмата (след като излезе, той никога не се връща обратно).
  • Следователно общият брой операции за целия масив е най-много 2N, което дава времева сложност O(N) и памет O(N).

Пример 1: Най-близък по-голям елемент вляво (Задача „Кули“)

Условие

  • Дадени са N кули в редица с височини a1, a2, …, aN.
  • Всяка кула излъчва лазерен лъч хоризонтално наляво.
  • Лъчът се спира от първата кула вляво, която е строго по-висока от излъчващата.
  • За всяка кула намерете индекса на кулата, която приема нейния сигнал (или 0, ако лъчът излиза извън редицата).

Правило

  • В стека почти винаги пазим индексите на елементите (1, 2, ..., N), а не самите им височини.
  • Чрез индекса idx винаги знаем както позицията му, така и височината му a[idx].

Трасировка: 5 кули (1-базирана индексация): a = [4, 2, 5, 1, 3]

Стъпка (i) Височина a[i] Извадени индекси Връх на стека (Отговор) Стек след стъпката
1 4 няма 0 (празен) [ 1(4) ]
2 2 няма 1 (вис. 4) [ 1(4), 2(2) ]
3 5 2 (вис. 2), 1 (вис. 4) 0 (празен) [ 3(5) ]
4 1 няма 3 (вис. 5) [ 3(5), 4(1) ]
5 3 4 (вис. 1) 3 (вис. 5) [ 3(5), 5(3) ]
Наблюдение:
На стъпка 3 пристига кула с височина 5. Тя е по-висока от кула 2 (вис. 2) и кула 1 (вис. 4), затова ги изваждаме от стека — те никога повече няма да спрат лъч на кула вдясно от 3-тата.

Имплементация на C++: mstack1.cpp

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1000005;
int n;
int a[MAXN];
int ans[MAXN];

int main()
{
    cin >> n;
    for(int i = 1; i <= n; i++) cin >> a[i];
    stack<int> st;

    for(int i = 1; i <= n; i++)
    {
        while(!st.empty() && a[st.top()] <= a[i])
        {
            st.pop();
        }

        if(st.empty()) ans[i] = 0;
        else ans[i] = st.top();

        st.push(i);
    }
    for(int i = 1; i <= n; i++)
    {
        cout << ans[i] << " ";
    }
    cout << "\n";
}

Пример 2: Най-голям правоъгълник в хистограма

Условие

  • Дадена е хистограма от N долепени вертикални стълба, всеки с ширина 1 и височина hi.
  • Намерете лицето на най-големия правоъгълник, който може да се впише изцяло вътре в хистограмата.

Идея

  • Най-големият правоъгълник задължително има височина, равна на височината на поне един от стълбовете, които покрива.
  • Ако фиксираме, че стълб i е най-ниският стълб в нашия правоъгълник (значи височината на правоъгълника е hi), колко най-много можем да го разширим наляво и надясно?

Анализ

  • Можем да го разширяваме наляво, докато не срещнем първия стълб с височина строго по-малка от hi: Нека неговият индекс е Li (ако няма такъв, Li = 0).
  • Можем да го разширяваме надясно, докато не срещнем първия стълб с височина строго по-малка от hi: Нека неговият индекс е Ri (ако няма такъв, Ri = N + 1).
  • Тогава правоъгълникът обхваща всички стълбове от Li + 1 до Ri − 1 включително.
  • Неговата ширина е Ri − Li − 1, а лицето му е:
Areai = hi · (Ri − Li − 1)
Наблюдение:
С два монотонно растящи стека (един от ляво надясно за масива L[] и един от дясно наляво за масива R[]) намираме границите за всеки стълб за O(N) време.

Числов пример: За хистограма h = [ 2, 1, 5, 6, 2, 3 ]

Стъпка (i) Височина a[i] Пръв по-малък вляво L[i] Пръв по-малък вдясно R[i] Широчина (R − L − 1) Лице
1 2 0 2 1 2
2 1 0 7 6 6
3 5 2 5 2 10
4 6 3 5 1 6
5 2 2 7 4 8
6 3 5 7 1 3
Извод:
За стълб i = 3 (височина 5) първият по-нисък вляво е на индекс 2 (височина 1), а първият по-нисък вдясно е на индекс 5 (височина 2). Той се разширява върху индекси 3 и 4, давайки ширина 5 − 2 − 1 = 2 и максимално лице 5 · 2 = 10.

Имплементация на C++: mstack2.cpp

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1000005;
int n;
long long h[MAXN];
int L[MAXN], R[MAXN];

int main()
{
    cin >> n;
    for(int i = 1; i <= n; i++) cin >> h[i];
    stack<int> st;

    for(int i = 1; i <= n; i++)
    {
        while(!st.empty() && h[st.top()] >= h[i])
        {
            st.pop();
        }
        L[i] = st.empty() ? 0 : st.top();
        st.push(i);
    }
    while(!st.empty()) st.pop();

    for(int i = n; i >= 1; i--)
    {
        while(!st.empty() && h[st.top()] >= h[i])
        {
            st.pop();
        }
        R[i] = st.empty() ? n + 1 : st.top();
        st.push(i);
    }
    long long max_area = 0;
    for(int i = 1; i <= n; i++)
    {
        long long width = R[i] - L[i] - 1;
        long long current_area = h[i] * width;
        max_area = max(max_area, current_area);
    }
    cout << max_area << "\n";
}

Пример 3: Стек от монохромни блокове (Задача „Цветни топчета / Zuma“)

Условие

  • В улей падат едно след друго N цветни топчета, всяко зададено със своя цвят ci.
  • Ако в даден момент се съберат K на брой последователни топчета от един и същи цвят, те веднага експлодират и изчезват, при което топчетата от двете им страни се долепят (което може да предизвика верижна реакция).
  • Колко топчета ще останат в улея след края на процеса?

Идея

  • Ако пазим всяко топче като отделен елемент в стека, при голямо K ще правим твърде много проверки назад.
  • Вместо това в стека пазим монохромни блокове като двойки (цвят, брой) →
  • Когато пристигне ново топче с цвят col, проверяваме върха на стека:
    • Ако върхът е със същия цвят col, просто увеличаваме брояча му с 1.
    • Ако върхът е с различен цвят (или стекът е празен), добавяме нов монохромен блок (col, 1).
    • Веднага след това проверяваме дали броят на топчетата на върха е станал равен на K.
    • Ако да — премахваме целия блок от върха (pop) за O(1) време!

Числов пример

Нека K = 3 и падат топчета с цветове: 1, 2, 2, 1, 2, 1, 1, 3.

  • Пада 1 → Стек: [ (1, 1) ]
  • Пада 2 → Стек: [ (1, 1), (2, 1) ]
  • Пада 2 → Слива се с върха: [ (1, 1), (2, 2) ]
  • Пада 1 → Стек: [ (1, 1), (2, 2), (1, 1) ]
  • Пада 2 → Стек: [ (1, 1), (2, 2), (1, 1), (2, 1) ]
  • Пада 1 → А ако вместо горните имахме 1, 2, 2, 2, 1, 1:
Извод:
При третата двойка блокът (2, 3) експлодира и остава [ (1, 1) ]. Следващите две единици се залепят директно към старата единица на върха, образуват (1, 3) и също експлодират (верижна реакция!).

Имплементация на C++: mstack3.cpp

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1000005;

struct Block
{
    int color;
    int cnt;
};
int n, k;
Block st[MAXN];
int top_idx = 0;

int main()
{
    cin >> n >> k;

    for(int i = 1; i <= n; i++)
    {
        int col;
        cin >> col;

        if(top_idx > 0 && st[top_idx].color == col)
        {
            st[top_idx].cnt++;
        }
        else
        {
            top_idx++;
            st[top_idx] = { col, 1 };
        }
        if(st[top_idx].cnt == k) top_idx--;
    }

    int rem = 0;
    for(int i = 1; i <= top_idx; i++)
    {
        rem += st[i].cnt;
    }
    cout << rem << "\n";
}

Тънкости и чести грешки

Строго срещу нестрого неравенство при дубликати

  • Когато търсите строго по-голям елемент, условие за изваждане от стека е a[st.top()] <= a[i] (изхвърляме и равните, защото те не ни вършат работа).
  • Когато обаче броите сума на минимумите на всички подмасиви, за да не преброите един и същ подмасив два пъти при равни елементи, от едната страна (напр. вляво) използвайте строго неравенство, а от другата (вдясно) — нестрого.

Масив срещу Стек

  • Симулирането на стек със статичен масив int st[MAXN]; int top_idx = 0; не само е по-бързо от std::stack, но ви позволява при нужда да надникнете във втория елемент под върха (st[top_idx - 1]) за O(1) време без да правите pop и push.
